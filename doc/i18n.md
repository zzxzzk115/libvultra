# Internationalization (i18n)

**English** | [简体中文](zh_CN/i18n_CN.md)

Vultra ships a small localization subsystem in the engine core (`I18nSystem`, exposed through the
`II18nService`). It serves the engine, the editor, and games built on the engine. The editor UI is
fully localized; a game can register and override its own catalogs.

Bundled editor languages: **English** (`en`, the source of truth and fallback), **Simplified
Chinese** (`zh-CN`), **Japanese** (`ja`), and **Korean** (`ko`).

## Catalogs

Catalogs are JSON, authored nested and flattened to dotted keys at load time
(`{"menu":{"file":{"save":"Save"}}}` becomes the key `menu.file.save`). Leaf values are strings; a
reserved top-level `"@meta": { "name": "..." }` object sets the locale's display name and is not
flattened. Files are named with their BCP-47 tag: `en.json`, `zh-CN.json`, `ja.json`, `ko.json`.

```json
{
  "@meta": { "name": "日本語" },
  "common": { "save": "保存", "cancel": "キャンセル" },
  "menu":   { "file": { "saveScene": "シーンを保存" } }
}
```

Every locale must have the **same key set** as `en.json` (English is the fallback for any miss). The
editor catalogs live in `builtin/i18n/` and are kept at exact key parity with `en.json`.

### Embedded delivery

The editor catalogs in `builtin/i18n/*.json` are packed (alongside shaders, fonts, textures, and
render graphs) into the build-time zstd `builtin.vpk` by the `vultra.builtin_pack` rule — the rule
globs `builtin/i18n/`, so a newly added file is picked up automatically with no codegen step. At
startup the editor reads the raw JSON straight from the pack via
`vultra::builtin::read("i18n/<locale>.json", ...)` and registers it with
`registerCatalog(locale, json, "editor", 100)` (see
`source/vultra_app/src/editor_app/editor_i18n.cpp`). No lz4 header embedding is involved.
(`registerCompressedCatalog()` still exists on the service for callers that ship lz4 blobs, but the
editor no longer uses it.) A game that ships catalogs on disk just reads the file and calls
`registerCatalog()` with the raw JSON text.

## Using translations in code

Include `vultra/core/i18n/i18n.hpp` and call the ambient free functions (they resolve through the
process-wide active translator, so deep UI draw code needs no `EngineContext`):

```cpp
ImGui::TextUnformatted(vultra::tr("inspector.transform.position")); // display text
ImGui::Text("%s", vultra::trf("entity.uuid", uuid).c_str());        // fmt format string + args
```

- `tr(key)` returns a frame-stable `const char*` (valid until the next `setLanguage`); a miss returns
  the key itself, so untranslated keys are visible and recorded by `missingKeys()`.
- `trf(key, args...)` translates a value that is a `fmt` format string, then formats it. **Placeholders
  (`{}`, `{:.2f}`, ...) must be identical across every locale** or `fmt::format` throws — the catalog
  build verifies this.

### ImGui id stability

ImGui derives a widget's id from its visible label up to `###`. A label that changes with language
would break docking (`imgui.ini`), open/close state, and popup matching. For any translated label that
is also an id (windows, buttons, menu items, tabs, popups), use `trId`:

```cpp
ImGui::Begin(vultra::trId("window.inspector.title", "InspectorWindow")); // 検査###InspectorWindow
if (ImGui::Button(vultra::trId("common.save", "btnSave"))) { ... }
```

The visible text follows the language; the `###StableId` keeps the widget id language-invariant.

## Switching and detecting the language

- `setLanguage(locale)` switches live; listeners registered with `onLanguageChanged` refresh.
  `availableLanguages()` / `displayName(locale)` drive the Editor Settings language dropdown.
- On first launch the editor detects the OS language (`detectSystemLocale()` →
  `resolveStartupLocale()`): Simplified Chinese → `zh-CN`, Japanese → `ja`, Korean → `ko`, otherwise
  `en`. The choice is persisted in editor settings and respected on subsequent launches.

## Catalog stacking (engine + editor + game)

Each registered catalog carries a `domain` and an `int priority`; the active map is the merge of all
catalogs for the current locale in ascending priority (higher wins). Convention: **engine 0, editor
100, game 200**. A game overrides any engine/editor string by registering its own value for the same
dotted key, while still inheriting everything it does not override.

```cpp
auto& i18n = ctx().services.require<vultra::II18nService>();
i18n.registerCatalog("en", myGameEnglishJson, "game", 200);
i18n.registerCatalog("ja", myGameJapaneseJson, "game", 200);
```

## Adding a language

1. Copy `builtin/i18n/en.json` to `builtin/i18n/<tag>.json`, set `@meta.name` to the endonym, and
   translate every value (keep the key structure and all format placeholders identical to `en.json`).
2. Add the new tag to the hard-coded locale list in `registerBuiltinEditorCatalogs()` (`{"en",
   "zh-CN", "ja", "ko"}`); the file itself is picked up from the pack automatically since
   `builtin_pack` globs `builtin/i18n/`. Add OS-locale detection in `resolveStartupLocale()` if
   desired.
3. Ensure the bundled font covers the new script. The editor merges a subset of **Noto Sans CJK**
   (SIL OFL) which already covers Chinese, Japanese, and Korean; a new script (e.g. Cyrillic, Thai)
   may need the font subset's keep-set extended in the font build.

## Fonts and HiDPI

CJK glyphs are folded into the default ImGui font from a bundled Noto Sans CJK subset
(`builtin/fonts/noto_sans_cjk.otf`), rasterized on demand by ImGui 1.92's dynamic atlas — no glyph
ranges or atlas rebuild on language switch.

UI scale is the user's **Application Scale** setting (Editor Settings → Appearance). It scales the
ImGui style via `ScaleAllSizes` and every hardcoded pixel literal via `ui::dp()`
(`vultra/function/imgui/imgui_dpi.hpp`); wrap design-pixel constants in `ui::dp(...)` so they track the
setting. The desktop OS DPI factor is fixed at 1.0 (Android applies its display density automatically).
